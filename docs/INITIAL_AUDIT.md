# تقرير التدقيق الأولي والفحص الهيكلي — MIZAN ACCOUNTING ULTRA
**المشروع:** Mizan Accounting Ultra (ترقية وتطوير Mizan Accounting Plus)  
**التاريخ:** أكتوبر 2026  
**الفريق الهندسي:** فريق الهندسة المحاسبية وتطوير النظم

## 1. فحص ملفات مساحة العمل (Workspace Audit)

### 1.1 حالة الملفات القائمة
- تم إجراء فحص شامل للملفات بحثاً عن أي ملف باسم `mizan-accounting-plus.html` أو ما يماثله في مساحة العمل.
- تبين أن المشروع يبدأ من بيئة React 19 + TypeScript + Vite + Tailwind CSS v4 مع أدوات متقدمة (`three`, `lucide-react`, `motion`).
- لم تكن هناك بيانات تاريخية مسبقة محفوظة في IndexedDB أو localStorage بحاجة للترحيل الفوري، مما يمنحنا فرصة هندسية استثنائية لبناء **نواة محاسبية غير متهاونة (Zero-compromise Double Entry Engine)** مع دعم معايير الترحيل والإصدارات اللاحقة (Schema Versioning & Migration Pipeline v1.0).

### 1.2 فحص التبعيات وحيادية التكلفة (Zero-Cost & Free-Tier Strictness)
- تم فحص التبعيات:
  - لا توجد أي خدمات مدفوعة ملزمة.
  - لا توجد أي اشتراكات سحابية إجبارية.
  - يعمل النظام بوضع **Offline-First** كامل.
  - محرك التخزين المحلي هو **IndexedDB** عالي الأداء مع طبقة أمان ونسخ احتياطي واستعادة مع التحقق من السلامة (Checksum & Validation).
  - معالجة الصور والتصميم البصري والباركود والرموز ثلاثية الأبعاد (3D) تعمل محلياً داخل المتصفح بنسبة 100% دون خوادم وسيطة أو رسوم API.

## 2. الثغرات الشائعة في برامج المحاسبة غير المتخصصة وتفاديها في MIZAN ULTRA

| الثغرة الشائعة | الحل الهندسي المطبق في Mizan Accounting Ultra |
| :--- | :--- |
| **اعتماد الحسابات على الفاصلة العائمة (Float Precision Errors)** | استخدام تمثيل مالي دقيق عبر أعداد صحيحة بوحدات المليم/السنت (Minor Currency Units) مع تقريب مالي منضبط `roundToDecimals` وحساب منفصل للكسور لمنع أخطاء `0.1 + 0.2 = 0.30000000000000004`. |
| **الأرباح الوهمية** | حساب صافي الأرباح الحقيقي عبر معادلة: `المبيعات - تكلفة البضاعة المباعة (COGS) - المصروفات التشغيلية - الخصومات الممنوحة + الإيرادات الأخرى` مع تتبع المرتجعات. |
| **القيود غير المتوازنة** | منع ترحيل أي قيد محاسبي إذا كان `مجموع المدين ≠ مجموع الدائن`. يتم رفض الترحيل قطعياً عند مستوى المحرك الأساسي (Kernel Level). |
| **تعديل المخزون بدون أثر محاسبي وتاريخي** | كل حركة مخزون (شراء، بيع، تسوية، هدر، جرد) تولد حركة مخزنية مرتبطة بمستند وقيد محاسبي يوثق تكلفة الوحدة والتكلفة الإجمالية. |
| **ازدواج الترحيل (Idempotency Bug)** | حماية جميع أزرار الحفظ والترحيل بمفاتيح أمان وتجزئة تمنع التكرار عند النقر المزدوج أو إعادة التقديم. |
| **فقدان الصور والتعديلات** | حفظ الصور الأصلية ومشاريع التعديل والقوالب بشكل مستقل مع تاريخ التعديلات (Undo/Redo). |

## 3. خطة الترحيل وضمان التوافق (Migration & Data Safety Plan)
1. **المخطط الترحيلي المستقبلي (Schema Migration Engine):**
   - تم تصميم بنية البيانات بإصدار `version: 1`.
   - عند أي تحديث مستقبلي يتم فحص رقم الإصدار وتطبيق ترقيات الحقول والجداول التراكمية تلقائياً.
2. **النسخ الاحتياطي الذكي:**
   - تصدير ملفات `.json` مشفرة أو مضغوطة تشمل: دليل الحسابات، قيود اليومية، الفواتير، المخزون، الحركات، قوالب الإعلانات، وبيانات الشركة.
   - التحقق من تماسك القيود قبل الاستيراد (Pre-import Ledger Integrity Verification).
